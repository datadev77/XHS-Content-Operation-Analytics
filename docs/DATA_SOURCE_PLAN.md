# 数据源获取与样本量方案

> 决策日期：2026-08-18
> 状态：已完成下载与首轮字段审计；首版纳入范围以 `DATA_AUDIT.md` 为准。

## 1. 推荐顺序

### 方案 A：公开研究数据集 RedNote-Vibe（首选起点）

- 仓库：https://github.com/ydli-ai/RedNote-Vibe
- 论文：https://arxiv.org/abs/2509.22055
- 许可：CC BY-NC 4.0，仅限非商业用途，使用时需要署名。
- 公开说明字段：标题、正文、发布时间、点赞、收藏、评论、内容领域，以及部分 AIGC 来源字段。
- 当前已下载规模：近期探索集91,517行、历史人工集51,878行、AIGC生成集7,254行。

选择理由：

- 有论文、字段说明和明确许可，比来源不明的付费数据包更容易在面试中解释；
- 同时包含文本、时间、领域和互动指标，足以完成清洗、PostgreSQL 建模、指标分析和内容分层；
- 具有“AI 生成内容与人工内容的表现差异”这一潜在差异化切口。

必须先验证的风险：

- 当前公开文件实际名为 `exploring_set.jsonl`，而 README 写作 `exploration_set.jsonl`；下载脚本使用实际文件名；
- 人工训练集主要来自 2022 年 11 月以前，不能用于声称 2026 年最新内容趋势；
- AIGC 子集可能是模型生成样本，不能未经核验就当作真实发布并获得互动的数据；
- 缺少曝光量、账号粉丝量和统一观察窗口时，不能计算真实互动率，也不能公平比较所有笔记；
- 下载后必须核对实际行数、重复率、时间范围、字段缺失和样本构造方法。

### 方案 B：自己的小红书创作者中心数据（有账号数据时优先补充）

如果用户本人运营过小红书账号，可从创作者中心导出或在本人授权登录状态下整理自己的数据。

优势：可能包含曝光、阅读、点击、粉丝和分时趋势，指标业务含义最强。

限制：个人账号通常笔记数较少，只适合作为真实案例或指标验证，不能代替大样本横向分析。登录凭据、Cookie 和原始个人数据不得提交 Git。

### 方案 C：少量近期公开样本（仅作为时间补充）

只有在方案 A 明显过旧、且能够遵守平台规则和个人信息保护要求时，才补充近期公开笔记。

要求：

- 只采集完成既定研究问题所需的最少字段；
- 不采集私密、登录受限或敏感个人信息；
- 对作者标识做哈希或删除，图片和头像默认不保存；
- 记录关键词、采集时间、发布时间、抽样规则和失败记录；
- 不绕过验证码、访问控制或平台风控；
- 使用第三方采集服务前，先核对数据许可与平台条款，来源不明的“全量数据包”不使用。

## 2. 不推荐方案

- 购买宣称数亿条但不能说明采集方法、许可和样本偏差的数据包；
- 直接使用 GitHub 爬虫大规模抓取并把登录 Cookie 写入代码；
- 为追求“大数据”而收集远超分析需求的数据；
- 使用合成数据冒充真实平台数据；
- 把搜索结果页的热门样本当成随机样本，却不披露推荐算法和幸存者偏差。

## 3. 样本量建议

### 最低可交付规模

- 笔记：3,000–5,000 条；
- 内容领域：至少 5 类，每类尽量不少于 500 条；
- 用途：数据清洗、SQL、描述分析、分层比较和轻量看板；
- 限制：不适合复杂模型，也不足以支持细分领域的稳定结论。

### 推荐规模

- 笔记：20,000–50,000 条；
- 内容领域：8–11 类，按领域和时间分层抽样；
- 用途：完整 MVP、稳健统计、敏感性分析和简单预测基线；
- 优点：单机 Python 与 PostgreSQL 足以处理，同时能形成有说服力的数据质量和查询案例。

### 上限规模

- 笔记：约 100,000–160,000 条；
- 用途：验证管道性能、全量领域比较或文本特征扩展；
- 说明：超过推荐规模不会自动提高面试竞争力。面试价值主要来自抽样设计、字段口径、数据质量和业务判断。

评论数据不进入第一版 MVP。若后续研究用户需求或情绪，再选择 10,000–50,000 条笔记对应的评论样本，并单独处理一对多关系、隐私与文本清洗。

## 4. 首轮下载与审计步骤

1. 运行 `powershell -ExecutionPolicy Bypass -File scripts/download_rednote_vibe.ps1` 下载 RedNote-Vibe 当前公开文件；脚本会校验 SHA-256，且不直接修改已有正确文件；
2. 保存来源 URL、下载日期、许可证和文件哈希；
3. 逐文件统计大小、行数、字段、编码、重复和 JSON 解析失败数；
4. 检查发布时间范围、领域分布和互动指标缺失率；
5. 随机抽查人工/AIGC 样本，核对字段含义和样本构造；
6. 判断哪些子集可用于真实运营分析，哪些只能用于方法演示或 AIGC 研究；
7. 近期探索集去重后约60,161篇，规模适合首版全量分析；历史集仅用于跨时期稳健性对照；
8. 审计通过后，再确定核心业务问题和 PostgreSQL 表结构。

## 5. 数据使用边界

- 项目报告必须注明数据并非小红书官方全量数据；
- 结论只适用于该数据集的采样领域、时间和样本构造；
- 无曝光量时只分析互动数量和互动结构，不命名为平台真实互动率；
- 无统一内容年龄时，发布时间比较必须控制累计时间或承认偏差；
- 不将观察性关系写成内容策略的因果效果；
- 数据文件默认不提交 Git，只提交来源、字段字典、清洗代码和可复现抽样规则。
