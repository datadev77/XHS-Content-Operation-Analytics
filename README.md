# 小红书内容数据质量与 SQL 训练案例

## 当前定位

这是一个基于公开研究数据的可复现数据质量审计案例，当前范围聚焦字段统一、异常候选识别、重复记录处理和数据边界说明。它不代表生产级数据平台，也不把观察性历史数据包装成真实运营实验。

项目使用 RedNote-Vibe 近期探索集。数据覆盖 2022 年 12 月至 2025 年 6 月；原始文件不纳入 Git。当前阶段的实际实现记录在 [`notebooks/01_data_audit.ipynb`](notebooks/01_data_audit.ipynb)，审计口径和已知限制见 [`docs/DATA_AUDIT.md`](docs/DATA_AUDIT.md)。

数据来源为 [RedNote-Vibe](https://github.com/ydli-ai/RedNote-Vibe)，按其 CC BY-NC 4.0 许可用于非商业学习与研究。详细来源、文件哈希和纳入范围见 [`docs/DATA_SOURCE_PLAN.md`](docs/DATA_SOURCE_PLAN.md)。

## 已完成（以 Notebook 当前代码和输出为准）

- 读取并统一 91,517 条原始记录中的三种字段结构，得到 60,161 个不同笔记 ID。
- 保留旧版异常标记，并实现已确认的新版候选规则：旧规则，或收藏/点赞、评论/点赞任一项达到相应绝对量不少于 100,000 且比例不少于 50。
- 新规则标记 230 条记录、涉及 217 个 ID；旧规则为 228 条，新增 2 条，正好是已审查的两条候选。
- 排除候选异常记录后剩 91,287 条；按笔记 ID 去重后得到 59,959 条、59,959 个唯一 ID。第二版结果没有重复 ID，确认新增的两条候选均未进入分析表。
- 生成 16 列的 Notebook 分析表；发布时间转换失败数为 0。原始数据未被修改。

这些数字描述的是该研究数据集及当前处理规则，不是小红书平台总体情况。按累计互动量优先选择同一 ID 的较高互动版本，可能偏向较晚抓取或累计时间较长的记录；其与采样偏差叠加后，不宜将去重后的互动量直接解释为内容质量或策略效果。

## 不能据此声称

数据没有曝光量/阅读量、粉丝量、转化、收入、统一观察时长或真实运营实验。因此不能构造真实互动率，不能公平地把不同累计时长的笔记当作同条件比较，不能证明发布时间最优，也不能声称某项建议会带来涨粉或商业收益。公开历史样本只支持其采样范围内的描述和谨慎的相关性讨论，不能代表 2026 年现状或全平台。

## 可复现与限制

复现依赖本地 `data/raw/` 中的原始数据文件（被 `.gitignore` 排除）及 Notebook 中按顺序运行的单元格。公开仓库若要复现，使用者需要先按数据源许可自行取得数据；本仓库不提供原始或处理后数据下载。本地已生成并回读验证 `data/processed/notes_clean_v2.csv`，清洗阶段的数量核对、字段说明和限制记录已经完成；这不等于整个项目已完成，下一阶段计划做小规模 SQL 应用练习。

最短复现步骤：

1. 使用 Python 3，并运行 `pip install -r requirements.txt` 安装依赖；
2. 在项目根目录运行 `powershell -ExecutionPolicy Bypass -File scripts/download_rednote_vibe.ps1`，下载并校验原始文件；
3. 打开 `notebooks/01_data_audit.ipynb`，从第一个单元格开始按顺序运行；
4. 清洗结果会保存至本地 `data/processed/notes_clean_v2.csv`，该文件不会进入 Git。
